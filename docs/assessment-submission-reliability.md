# 测评提交：时间预算与安全重试

范围：`POST /api/reports/assessment-profiles` 及其浏览器提交、第三方同步和持久化调用。
核对基线：`2be3a644cd5eb30fe2d0f2dab55281a787dfb6a4`。

原实现的 `maxDuration = 120` 秒，但 `retries: 1`、每次 90 秒允许第三方同步占用 180 秒；
`Promise.race` 超时也没有取消请求和评分轮询。每次请求使用随机底稿、订单 ID，重试会重复创建。
这些是代码层面的风险，不代表已发生线上事故，也未确认是否有真实客户使用此链路。
2026-07-07 审计第 13 节已经记录的安全修复继续保留。

## 时间预算

| 项目 | 上限 / 处理 |
| --- | --- |
| 平台配置 | `maxDuration = 120` 秒，保持不变 |
| 应用截止时间 | 从 POST 入口起 110 秒；各步骤按剩余时间缩短，保留约 10 秒平台余量 |
| 请求体读取 / 底稿查询 | 各 5 秒 |
| 第三方单次尝试 | 最多 40 秒，含建会话、分页答题、触发评分、轮询、响应正文读取 |
| 第三方全部尝试 | 最多 80 秒；最多 2 次，重试共用总预算 |
| 尾部预留 | 同步截止时间不得晚于应用截止前 25 秒 |
| 底稿插入 / 订单查询 / 价格配置读取 / 订单插入 | 各最多 5 秒，全部受应用截止时间约束 |
| 活动日志 | 最多 1 秒；日志失败不改变已确认的提交结果 |
| 本地评分及其他计算 | 尾部 25 秒扣除上述 21 秒 I/O，约 4 秒余量 |

同步预算公式：`max(0, min(80 秒, 应用剩余时间 - 25 秒))`。
本地评分使用现有同步算法，不调用外部服务。一次开发环境离线检查中，252 道模拟答案运行
25 次，平均约 2.03 毫秒、最慢约 5.38 毫秒；这不是生产性能承诺。
JavaScript 同步计算、进程暂停及平台更短的硬限制无法通过定时器抢占；未读取或调整生产配置。

超时会中止 fetch、正文读取及评分轮询等待。每阶段检查取消信号，超时后迟到的结果不能启动下一阶段。
本地结果保留 `mode: "local"`、回退原因与实际尝试次数，不伪装成第三方原始结果。

## 提交与恢复约定

- 请求必须带 UUID 格式的 `submission_id`。浏览器在发送前把提交编号和请求内容写入本地存储；
  失败、刷新和丢失响应后，相同内容复用编号。显式清空草稿或更改提交内容会生成新编号。
- 底稿、自动 lite 订单使用“租户 + 提交编号 + 资源类型”派生的固定 UUID。
  Supabase 使用已有主键唯一约束处理并发冲突；不需要新表、迁移或后台任务。
- 底稿只在首次提交时插入。相同编号但不同内容返回 `409 submission_conflict`，不覆盖底稿，
  不返回原底稿内容。内容哈希忽略 JSON 对象键顺序，保留数组顺序。
- 重试已保存底稿时不重新同步或评分；只补齐缺少的订单。已有订单不被重置，支付、交付状态保留。
- 数据库超时不代表事务一定没有提交。客户端必须使用原编号重试，以确认原记录而非创建新记录。
  两个并发首次请求仍可能各自进行第三方同步；最终只保存一份底稿、一条自动订单。
- 本地 FileStore 仅支持单进程开发用途；跨实例并发保证来自生产 Supabase 的主键约束。
  原有“生产缺数据库拒绝降级到本地存储”的规则保留。

| 响应 | 含义 / 客户端动作 |
| --- | --- |
| `200` | 底稿和订单均已确认保存；返回结果来源、尝试次数及签名链接 |
| `400` | 输入无效、缺少提交编号或未完整包含题库中 252 道题；未开始同步 |
| `409` | 编号与内容冲突；不能用同一编号覆盖不同内容 |
| `503 submission_retryable` | 保留草稿，按 `Retry-After: 2` 使用原编号和内容重试 |
| `503` 且 `profile_saved: true` | 底稿已确认保存，订单阶段未完成，可直接重试补齐 |
| `503` 且 `profile_saved: false` | 尚未确认保存结果；可能已提交，仍应使用原编号重试 |

旧版打开的页面需刷新后重试，原草稿键保持不变。其他 API 客户端须同步增加 `submission_id`。
历史上没有提交编号的记录不会被自动去重；新提交也不会按姓名或联系方式合并不同测评。
如果用户删除浏览器存储或换设备且没有保留提交编号，不能自动判断是否为同一次提交。

`PRINCIPLESYOU_COLLECT_PATH` 自定义采集器须导出 `supportsAbortSignal = true`，并在
`createSession(signal)`、`getQuestions(session, signal)`、`postAnswers(session, answers, signal)`、
`score(session, signal)` 中遵守取消信号。旧适配器缺少声明时直接本地回退，不启动其网络流程。

## 验证边界

自动化测试覆盖慢成功、各同步阶段连续超时、正文卡住、轮询取消、迟到结果、本地回退、
预算扣减、重复及并发提交、编号冲突、写入成功但响应丢失、部分写入后恢复、日志和数据库卡住。
存储测试用真实 Supabase/PostgREST 客户端配合模拟 HTTP 验证取消信号及 `23505` 冲突恢复；
没有连接真实数据库。测试数据均为人工构造，未调用真实第三方测评服务、读取客户数据或操作生产环境。

验证命令：`npm run typecheck`、`npm run lint`、`RUN_LIVE_SOURCE_DISCOVERY=0 npm test`、
`NEXT_TELEMETRY_DISABLED=1 npm run build`。原有 3 个依赖外部本地夹具的测试继续跳过。
